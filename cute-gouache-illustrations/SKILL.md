# Cute Gouache Illustrations

## 核心定位

把偏硬、偏抽象的内容，变成一个**温暖、可爱、正在发生事情的小世界**。

这里的“可爱”不是装饰层。角色、机器、箱子、轨道、植物、书本、便签等物件都应该参与解释观点。

一张合格的图应该做到：

1. 第一眼觉得亲切，愿意停留；
2. 第二眼看懂角色正在做什么；
3. 1–3 秒内理解这个动作为什么能解释观点；
4. 去掉文字后，画面仍然有基本逻辑；
5. 去掉角色后，如果概念完全不受影响，说明角色只是装饰，需要重做。

## 工作流

### 1. 先找真正值得画的认知锚点

读文章、帖子、Markdown、截图、链接或用户主题，优先提炼：

- 反常识判断
- 一个关键机制
- 一个前后变化
- 一个因果关系
- 一个流程中的断点
- 一个值得记住的行动原则

不要平均切段，也不要为了凑图而画普通事实。

### 2. 把抽象关系变成物理动作

先回答：**这句话如果真的发生在一个小房间里，会发生什么？**

可用的动作包括：

- 把混乱的东西分类
- 把断掉的线接起来
- 把原料送入机器再输出成品
- 把太大的东西压缩
- 把小东西放大
- 把漏掉的东西接住
- 把堆积的东西疏通
- 把不同容器里的东西合并
- 把噪音过滤掉
- 把一条长路径拆成小站点
- 给模糊的东西贴标签
- 把一个想法从草稿推进到交付

不要先用商业图标。优先让“动作”成立。

### 3. 再把动作放进可爱小世界

默认世界观：

- 桌面工作坊
- 小型工厂
- 手作实验室
- 邮局 / 分拣站
- 温室 / 花园
- 厨房 / 烘焙台
- 维修间
- 书店 / 档案室
- 小车站 / 输送带
- 玩具尺寸的城市设施

场景需要有一个清晰主动作，不要堆满“可爱小物”。

### 4. 角色承担核心任务

默认可以使用一个弱重复的原创角色：**Tiny Maker / 小芽创客**。

角色规则：

- 圆润、软乎、奶油白或浅暖色身体；
- 简单点状眼睛、轻微腮红、非常简洁的嘴；
- 可有一个小叶芽、围裙、工具袋或帽子作为识别元素；
- 不需要每张都出现；
- 出现时必须在搬、接、筛、贴、推、修、浇、分拣、装配等；
- 不要永远站在边上指着东西笑。

不要机械复刻任何参考图里的兔子、猫、机器或服装组合。角色语言统一即可，造型可以重新设计。

### 5. 选择画布

用户未指定时：

- 公众号 / 博客正文图：默认 `4:3`；
- 横版解释图：`16:9`；
- 小红书轮播：`3:4`；
- Instagram / 通用社媒：`4:5`。

系列内比例必须一致。

### 6. 文字要短

图内文字优先控制为：

- 0–1 个主标题；
- 0–5 个短标签；
- 每个标签 2–8 个中文字；
- 少量箭头、圈线、星星、心形、手写强调。

不要塞长段正文。

如果中文准确性比视觉更重要，宁可减少字，让正文承担解释。

### 7. 默认构图

优先使用以下几类：

**A. 左乱 → 中处理 → 右整齐**  
适合流程、工作流、信息整理、Agent。

**B. 一个中央大装置 + 角色操作**  
适合机制、系统、模型能力、工具。

**C. 两个并列小世界**  
适合前后对比、错误做法 vs 正确做法。

**D. 一条可爱的路径 / 车站 / 接力线**  
适合阶段、交付、协作、成长。

**E. 一张桌面小剧场**  
适合单个判断、心理状态、方法论。

连续两张不要完全同构。

### 8. 生图时的视觉约束

明确要求生成时，提示词至少包含：

- warm cream / off-white textured paper
- cute gouache and crayon illustration
- visible dry-brush and waxy grain
- pastel teal, peach pink, butter yellow, coral orange, lavender accents
- rounded friendly handmade shapes
- tiny maker character actively performing the core action
- cozy low-tech workshop world
- sparse handwritten labels
- clear visual metaphor
- generous breathing room
- charming but not childish
- editorial storybook explainer

同时明确排除：

- glossy 3D
- vector corporate illustration
- anime rendering
- tech dashboard
- PPT infographic
- photorealistic scene
- excessive candy colors
- dense typography
- mascot standing idle

### 9. 一组图要统一“世界”，不要统一“模板”

固定：

- 暖奶油纸张
- 粉彩青绿 / 蜜桃 / 奶黄 / 珊瑚橙主色系
- 相近蜡笔水粉颗粒
- 相近角色语言
- 相近手写字气质

变化：

- 场景类型
- 物件
- 角色动作
- 镜头远近
- 构图方向
- 隐喻方式

### 10. 不要复制参考图

参考图用于抽取：

- 材质
- 色板
- 留白
- 可爱程度
- 场景叙事
- 角色参与方式

不要照搬：

- 精确角色形象
- 原文案
- 同一台机器
- 同一堆便签
- 同一只猫
- 同样的左右布局
- 精确道具组合

同一主题也要重新设计新场景。

### 11. Shot list 模式

用户说“先规划 / 先分析 / 不要生图”时，输出：

- 序号
- 核心判断
- 小世界场景
- 核心物理动作
- 角色在做什么
- 关键物件
- 图内短标签
- 构图类型

5–8 张为常见范围。

### 12. 直接生成模式

用户明确要求“生成 / 画 / 做图”时，不要停在审美建议。

每张图单独生成，不要先做九宫格。

系列图生成顺序建议：

1. 先做最能代表风格的一张；
2. 确认角色、纸张、色板、笔触；
3. 再扩展剩余页面；
4. 最后统一 QA。

### 13. QA

生成后检查：

- 是否一眼就是蜡笔 × 水粉，而不是塑料 3D？
- 是否可爱但没有幼儿园素材感？
- 角色是否真的承担动作？
- 是否一个场景只解释一个核心机制？
- 是否还有足够留白？
- 色板是否稳定？
- 中文是否准确？
- 去掉文字后场景逻辑是否仍成立？
- 是否不小心复刻了旧案例？

详细见 `references/qa-checklist.md`。

### 14. 保存交付

在 workspace 内工作时，默认保存到：

```text
assets/<article-slug>-cute-gouache/
```

命名：

```text
01-cover.png
02-core-idea.png
03-mechanism.png
04-contrast.png
...
```

不要覆盖旧图片，除非用户明确要求。

## 输出口径

### 只规划

直接给 shot list，少讲美术理论。

### 直接生成后

说明：

- 一共生成几张
- 每张在解释什么
- 哪张最适合做封面 / 首图
- 哪张需要二次修字或构图
- 保存路径（如果有）

让图片承担主要表达。
